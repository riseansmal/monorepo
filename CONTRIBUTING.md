# Contributing

Start with [README](README.md) and [AGENTS](AGENTS.md). Use pinned runtimes, native lockfiles and the declared project structure. Run `pnpm check`, `pnpm build` and relevant integration/native proofs. Add meaningful behavioral regression coverage when changing functionality.

Follow [change control](docs/change-control.md) for exact intent, approved staging, commit previews and maintenance messages. Every reusable project needs appropriate native targets and honest capability diagnostics. An unavailable tool is not a passing check.

New repositories use the launch-only `initial commit` exception. Later work uses ordinary feature branches and reviewed commits. Remote creation, pushes, PRs, merges, releases and deployments each require appropriate authorization. Checked-in workflows do not establish branch protection or hosted permissions.

Keep setup instructions in README and references in docs. Remove obsolete guidance; preserve required legal notices. Update monorepo compatibility and migration notes when changing client-facing behavior. Client adoption is always opt-in.
